## Bug Fixes

### CodeBuddy、ZCode、Trae 上任务启动后不生效

在这三个平台上，`task.py start` 显示成功，但之后每一轮仍然说没有活动任务。Trellis 用错误的名字去读会话记录——这三家都用一个 Claude 兼容变量标识自己，而 Trellis 先查了那个变量。

在 CodeBuddy 上 hook 还找不到项目：IDE 上报的工作目录是 `/`，Trellis 直接采信了。

两个问题都已修复。跑 `trellis update` 获取新的 hook，然后重启 IDE。

### PreToolUse 工具名

这几个产品的 IDE 版和 CLI 版工具命名不同，之前注册的是 IDE 从不发送的名字。

| 平台      | 现在匹配                                                |
| --------- | ------------------------------------------------------- |
| CodeBuddy | `execute_command`、`Bash`、`PowerShell`、`task`、`Task` |
| Trae      | `RunCommand`、`Bash`                                    |

## Enhancements

### `trellis mem` 返回 compact 过的对话

会话一旦 compact，`trellis mem` 此前只返回 compact 之后幸存的部分——常常是几百轮里的两三轮。其余内容其实还在会话文件里。

现在这些轮次会返回，并标出每次 compact 的位置。一个 compact 过两次的 Codex 会话从 2 轮变为 18 轮，一个 Claude 会话从 100 变为 1536。工具调用、reasoning 和系统提示仍照旧剥离。

有些内容确实无法恢复，现在会明说而不是看起来完整：Codex 对 agent 之间的消息加密，Grok 把 compact 前的对话存为 `<session>/compaction/` 下的 markdown。

搜索结果会有小幅变化。只在 compact 摘要里匹配到的会话不再命中，而真实对话涉及该话题的会话开始命中。

### `trellis mem` 支持 Grok 会话

```bash
trellis mem search "关键词" --platform grok
trellis mem extract <session-id>
```

读取 `~/.grok/sessions/`，项目范围过滤与其他平台一致。
